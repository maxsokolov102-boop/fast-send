# QuickShare — мгновенный обмен текстом и файлами по коду

Минималистичный тёмный веб-сервис для обмена текстом и файлами (до 5 МБ)
между двумя устройствами по одноразовому 6-значному коду и паролю.
Relay-сервер на Node.js + WebSocket, фронтенд — чистый HTML/CSS/JS без фреймворков.

## Запуск локально

```bash
npm install
npm start
```

Сервер поднимется на `http://localhost:3000` (порт можно задать через
переменную окружения `PORT`).

Откройте страницу на двух устройствах/вкладках:
1. На первом — вкладка «Моё устройство»: получаете код (например `423 463`)
   и пароль (например `vwrfy0`).
2. На втором — вкладка «Подключиться»: вводите код и пароль, нажимаете
   «Подключиться».
3. После соединения доступен обмен текстом и файлами (drag&drop или выбор файла).

## Как это устроено

- **Код и пароль** генерируются на сервере при создании сессии и
  автоматически обновляются каждые 15 минут (`CODE_TTL_MS` в `server.js`).
  Обновление кода не разрывает уже установленное соединение — оно лишь
  делает старый код недействительным для новых подключений.
- **Пароль можно отключить** переключателем «Запрашивать пароль при
  подключении» — тогда подключиться можно будет по одному коду.
- **Relay, не хранилище**: сервер держит в памяти только активные сессии
  (код → сокеты хоста и гостя) и пересылает сообщения между ними напрямую.
  Тексты и файлы нигде не сохраняются на диск и удаляются из памяти сразу
  после пересылки/разрыва соединения.
- **Лимит файла** — 5 МБ, проверяется на сервере (`MAX_FILE_BYTES`
  в `server.js`) и дублируется на клиенте для мгновенной обратной связи.
- **Rate-limit** — для каждого IP считаются попытки ввода кода/пароля в
  скользящем окне (`RATE_WINDOW_MS`/`RATE_MAX_ATTEMPTS`); при превышении
  IP блокируется на `RATE_LOCKOUT_MS` (по умолчанию 5 минут). Это защищает
  от перебора 6-значного кода.

## HTTPS / WSS в продакшене

Сам Node-процесс отдаёт обычный HTTP/WS — TLS-терминацию рекомендуется
вынести на реверс-прокси (Nginx, Caddy, облачный балансировщик и т.п.),
который слушает 443 и проксирует на порт приложения. Например, для Nginx:

```nginx
server {
    listen 443 ssl;
    server_name example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

Клиентский код сам переключается на `wss://`, когда страница открыта по
`https://` (см. `public/app.js`, функция `connectSocket`).

## Что стоит доработать перед реальным продакшеном

- Хранить `rateBuckets` и активные сессии в Redis, если сервис будет
  работать на нескольких инстансах (сейчас — только в памяти одного процесса).
- Добавить лимит на общее число одновременных сессий / соединений с одного IP.
- Передавать крупные файлы чанками, а не одним base64-блоком, если планируется
  поднимать лимит выше нескольких мегабайт.
- Логирование и метрики (без логирования содержимого сообщений/файлов).
